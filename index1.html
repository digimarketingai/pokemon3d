What is AR Game Localisation?什麼是 AR 遊戲在地化？

Localisation (L10n) means adapting a product so it feels native to a target market, not just translating words. In augmented reality, text sits on a live camera view, moves with 3-D objects and competes with the real world for attention. That adds constraints ordinary software does not have. 在地化（L10n）是讓產品在目標市場顯得「本來就是當地產品」，而不只是翻譯文字。在擴增實境中，文字疊在即時相機畫面上、隨 3D 物件移動，還要與真實世界爭奪玩家注意力，限制比一般軟體更多。

🔁 The localisation pipeline (teaching model)🔁 在地化流程（教學模型）

Niantic's internal tools are not public. This model combines what is visible in the game with standard live-service industry practice.Niantic 的內部工具並未公開。本模型結合遊戲中可觀察到的現象與業界持續營運遊戲的常見做法。

1
String externalisation字串外部化

Text lives outside the code as key → value pairs, e.g. appeared: “Wild {n} appeared!”文字以「鍵 → 值」形式存放在程式之外，例如 appeared：“Wild {n} appeared!”

2
Official termbase官方術語庫

The IP owner supplies locked names (妙蛙種子, 小火龍, 傑尼龜…).版權方提供鎖定譯名（妙蛙種子、小火龍、傑尼龜……），不得更動。

3
TM + MT / LLM draft翻譯記憶＋機翻／大模型初稿

Recurring event text and UI strings are pre-filled automatically.重複出現的活動文字與介面字串由系統自動預填。

4
Human post-editing ★人工譯後編輯 ★

Fix meaning, terms, placeholders, length and locale.修正語意、術語、佔位符、長度與地區用語。

5
In-context LQA情境語言品質檢測

Test on real devices, over the camera view, in every language.在真機與真實相機畫面上，逐一語言測試。

6
Live-ops release營運上線

Weekly events mean tight deadlines; the cycle repeats constantly.每週都有活動、時程緊迫，流程不斷循環。

LLM Translation Problems: Claude, Gemini, GPT & Co.大型語言模型翻譯問題：Claude、Gemini、GPT 等

Studios increasingly draft localisation with LLMs instead of classic neural MT. The latest evidence shows LLMs are now the strongest translation systems overall, but their errors are different and often harder to see, because they are fluent. 越來越多遊戲公司改用大型語言模型（而非傳統神經機器翻譯）產生在地化初稿。最新研究顯示，LLM 整體已是最強的翻譯系統，但其錯誤類型不同，而且因為譯文流暢而更難察覺。

Fluent ≠ true

The most dangerous errors read well最危險的錯誤讀起來很順

Hallucinations and omissions are mostly fluent, which misleads users into trusting them (benchmark of 18 translation directions). GPT models also produce less literal translations than NMT: good for idioms, risky for locked terms.幻覺與漏譯多半很流暢，因而誤導使用者信任（涵蓋 18 個翻譯方向的基準）。GPT 模型的譯文也比神經機器翻譯更不直譯：利於慣用語，卻不利於鎖定術語。

Structure is not always preserved結構未必能保留

WMT25 sent whole multi-paragraph documents. A summary of the WMT25 data reports intact paragraph structure for GPT-4.1 97.1%, Gemini 2.5 Pro 95.1%, Claude 4 67.5% and DeepSeek-V3 57.2% of the time; failures were re-translated paragraph by paragraph. For JSON or UI files, broken structure = broken game.WMT25 以多段落完整文件送譯。一份 WMT25 資料摘要報告的段落結構完整率為：GPT-4.1 97.1%、Gemini 2.5 Pro 95.1%、Claude 4 67.5%、DeepSeek-V3 57.2%；失敗者改為逐段翻譯。在 JSON 或介面檔中，結構損壞＝遊戲壞掉。

Secondary summary of Kocmi et al., 2025 (verify in paper)
Model versions: the systems tested (Claude-3.5-Sonnet in 2024; Gemini 2.5 Pro, GPT-4.1, Claude 4 in 2025) have since been superseded. Read these results as evidence about model families and persistent error patterns, not a ranking of today's versions. The patterns (fluent errors, verbosity, short-string risk, format breakage, over-editing) are exactly what post-editors must check.模型版本：受測系統（2024 年的 Claude-3.5-Sonnet；2025 年的 Gemini 2.5 Pro、GPT-4.1、Claude 4）均已推出更新版本。請把這些結果視為關於模型家族與持續存在的錯誤模式的證據，而非現行版本的排名。這些模式（流暢的錯誤、冗長、短字串風險、格式損壞、過度編輯）正是譯後編輯必須檢查的重點。

★ Post-Editing Methods & Strategies (Core)★ 譯後編輯方法與策略（核心）

Post-editing (PE) means a human revises machine output (from NMT or an LLM) until it is fit for purpose. In game UI it must be accurate, official, functional and on-screen. 譯後編輯（PE）是由人工修訂機器輸出（神經機器翻譯或 LLM），直到符合用途。在遊戲介面中，譯文必須準確、合乎官方、功能正常，並放得進畫面。

A. Light vs Full post-editing (ISO 18587:2017)A. 輕度與完整譯後編輯（ISO 18587:2017）

Light post-editing輕度譯後編輯

Make the text understandable and accurate; fix only meaning errors. Fine for internal gisting. ❌ Not acceptable for player-facing UI.讓譯文可理解且正確，只修語意錯誤。適用於內部參考。❌ 不適用於玩家看得到的介面。

Full post-editing完整譯後編輯

Output must match human-translation quality: accuracy, terminology, style, locale, grammar, and in AR, on-screen fit. ✅ Required for game text.成品須達到人工翻譯品質：準確、術語、文體、地區、語法，在 AR 中還要放得進畫面。✅ 遊戲文字必須採用。

Golden rule黃金法則

Use as much of the raw output as possible. Do not rewrite correct strings: over-editing costs time and creates inconsistency.盡量沿用原始輸出。不要改寫已正確的字串：過度編輯既浪費時間，又造成不一致。
